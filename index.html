survey-weighted-analyses

Import, cleaning, description, imputation, and modeling of complex survey data in R

Author

David Pletta

Published

October 26, 2026

Preface

This book walks through a complete analysis of complex survey data in R, from downloading the raw file to reporting a multivariable model:

  1. importing a large survey file (1  Importing the Data);
  2. cleaning and recoding it with explicit checks (2  Cleaning and Recoding);
  3. describing the population with survey-weighted statistics (3  Descriptive Statistics);
  4. multiple imputation of missing data that respects the survey design (4  Multiple Imputation);
  5. bivariate (crude) models (5  Bivariate Models);
  6. multivariable (adjusted) models, a sensitivity analysis, and reporting (6  Multivariable Models).

It is written for students who know some R and the basics of regression, and who are new to survey weights or multiple imputation.

The question

Is household income associated with diabetes among US adults? Diabetes is common, costly, and unequally distributed. Income shapes access to healthy food, safe places to be active, health care, and the time and resources to manage a chronic condition. We estimate how the prevalence of diabetes differs across income groups, before and after accounting for age, sex, and race and ethnicity. An exercise in 6  Multivariable Models repeats the analysis for fair or poor general health.

The data

We use the 2024 Behavioral Risk Factor Surveillance System (BRFSS): telephone interviews with 457,670 adults, weighted to represent the US adult population. The data are public. You download them yourself (1  Importing the Data) and they stay on your computer.

Setup

  1. Install R (version 4.6.1 was used to build this book), Quarto, and an editor such as RStudio or Positron.
  2. Open the project: double-click survey-weighted-analyses.Rproj (RStudio) or open the folder (Positron).
  3. Install the packages: in the R console, run renv::restore(). This installs the exact package versions the book was built with into the project (see Appendix B — Reproducibility).
  4. For interactive chunks, run setwd("book") in the R console first. Download the data by opening book/01-import.qmd and running the download chunk once.

Then render the book from the terminal with quarto render book (the result is book/_book/index.html), or run the chapters’ code chunk by chunk, in order. Each chapter saves what the next one needs in data/processed/. Rendering time depends on available memory, processor cores and the number of imputations.

The import, survey tables, imputations and model fits reuse cached calculations on subsequent renders (see Calculate once, then reuse and Appendix B — Reproducibility). For descriptive statistics alone, run Chapters 1–3 and stop there.

For a quick test of the whole pipeline, quarto render book --profile smoke uses 2 imputations instead of 5 and writes to separate folders (book/_book-smoke/, data/processed-smoke/), so it never replaces the real results.

How the code is written

  • Every function is called with its package name, as in dplyr::mutate(), so you always know where a function comes from (and packages cannot silently mask each other).
  • |> is R’s pipe: x |> f() means f(x).
  • Lines that start with # Check: stop the code with an error if an assumption about the data fails. A silent check means the data are as expected.
  • tidylog:: versions of dplyr verbs print what each step did (rows dropped, variables created, share missing).
