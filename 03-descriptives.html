Descriptive statistics answer “what does the population look like?” With a complex survey, every estimate has to use the survey design, or it describes the sample (who happened to answer the phone) rather than the population (US adults). This chapter describes the observed data only: the answers people gave, with missing answers shown as missing. Imputed values (Chapter 4) are for models, not for describing who answered what.

3.1 The survey design object

The srvyr package lets us describe the design once and then use familiar dplyr verbs on it. The design object stores the data together with the three design features from Chapter 1:

  • ids: the primary sampling units (clusters);
  • strata: the strata;
  • weights: the final weight.

# Check again when reading a saved file: identifiers are nested and weights are valid.

TipWhy check_strata = FALSE?

By default the design checks that every PSU lies within a single stratum. Depending on the survey package version, this check can create a large PSU-by-stratum table. The psu_id variable numbers each stratum-PSU pair, so the PSUs are nested in strata by construction. Chapter 2 verifies that each identifier belongs to exactly one stratum before this check is disabled. Keep the default check unless you have verified that nesting condition.

The weights add up to the number of adults the sample represents: 263,783,390.

WarningWhat ignoring the design does
  • Without weights, estimates describe the sample, not the population. Groups that answer surveys more often (older adults, for example) count too much.
  • Without strata and clusters, standard errors are wrong, so confidence intervals and p-values are wrong too. Clustering usually makes them too small.

3.4 Table 2: outcomes by income

Adding by = income splits the table by income group, and gtsummary::add_p() tests whether each outcome differs across the groups. For categorical variables in survey data the test is the Rao-Scott test, reported as a design-adjusted F test by survey::svychisq(statistic = "F"). It accounts for weights, strata, and clusters.

3.5 Testing a continuous variable

Does mean age differ across the four income groups? age is the numeric BRFSS variable _AGE80: CDC-imputed age in years, with everyone aged 80 or older recorded as 80. The comparison therefore concerns this capped age variable, not exact age above 80. See the CDC calculated-variable definitions. The regression chapters continue to use age_group.

First select respondents with known income from the full survey design. Report weighted means and 95% confidence intervals before interpreting a test.

income_design <- design |> dplyr::filter(!is.na(income))

For more than two groups, fit a survey-weighted linear model and test the income coefficients together. With four groups there are three coefficients; the null hypothesis is that all three are zero, so all four population means are equal. The joint Wald F test uses the survey design for its variance.

Code 
age_fit <- survey::svyglm(age ~ income, design = income_design)
age_test <- survey::regTermTest(age_fit, ~income, method = "Wald")
rm(age_fit) # Cache the test result rather than the full model.

The p-value is <0.001. A small p-value is evidence that at least one mean differs; it does not identify which pairs differ or establish that a difference is practically important. Use the means and confidence intervals to describe the size of the differences.

3.5.1 Put the mean test in a summary table

gtsummary::add_p() accepts a short custom function returning a p-value. This function applies the same model and joint test to a numeric variable and a categorical grouping variable.

Code 
mean_test <- function(data, variable, by, ...) {
  fit <- survey::svyglm(stats::reformulate(by, variable), design = data)
  test <- survey::regTermTest(fit, stats::reformulate(by), method = "Wald")
  tibble::tibble(
    p.value = as.numeric(test$p),
    method = "Survey-weighted joint Wald test of means"
  )
}
Code

The parentheses contain the weighted standard deviation, which describes variation in age, rather than the standard error of the mean. In a table with both variable types, use all_continuous() ~ mean_test and all_categorical() ~ "svy.chisq.test" in the test list.

For two groups, survey::svyttest() is a direct test of the difference in means; the corresponding gtsummary alias is "svy.t.test". The alias "svy.wald.test" instead calls a contingency-table test of independence and should not be used to test continuous means. See the gtsummary test definitions. Ordinary t.test() and aov() do not account for this survey design.

3.7.2 The design changes the uncertainty

The design effect (DEFF) compares the variance of an estimate under the survey design with its variance under a simple random sample of the same size:

\[ \text{DEFF} = \frac{\text{Variance}_\text{survey design}}{\text{Variance}_\text{simple random sample}}, \qquad n_\text{effective} = \frac{n}{\text{DEFF}} \]

A DEFF of 2 means the survey gives as much information as a simple random sample half its size, and standard errors are \(\sqrt{2} \approx 1.4\) times larger.

Code 
design_effects <- design |>
  dplyr::summarise(
    diabetes = srvyr::survey_mean(diabetes_yes, na.rm = TRUE, deff = TRUE),
    n_diabetes = srvyr::unweighted(sum(!is.na(diabetes_yes))),
    fair_poor = srvyr::survey_mean(fair_poor, na.rm = TRUE, deff = TRUE),
    n_fair_poor = srvyr::unweighted(sum(!is.na(fair_poor)))
  ) |>
  dplyr::mutate(
    n_effective_diabetes = n_diabetes / diabetes_deff,
    n_effective_fair_poor = n_fair_poor / fair_poor_deff
  )

The unweighted prevalence of diabetes is 14.4%; weighted, it is 12.5%. The design effect is 5.1 for diabetes and 5.25 for fair or poor health, so the 456,636 answers about diabetes carry as much information as about 89,595 answers from a simple random sample. ImportantThree kinds of missing data
  • Missing completely at random (MCAR): missingness is unrelated to anything. Dropping incomplete answers loses precision but does not bias estimates.
  • Missing at random (MAR): missingness depends on observed variables (here, age and health). Dropping incomplete answers can bias estimates; multiple imputation that includes those variables does not.
  • Missing not at random (MNAR): missingness depends on the missing value itself (for example, people with very high incomes declining to say). Neither approach fixes this on its own; it calls for sensitivity analyses.

Income missingness varies with age and health, so MCAR is not plausible. Chapter 4 works under MAR, the standard assumption for multiple imputation.
